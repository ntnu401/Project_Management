系統專案進度提報

```
需求 → 規格 → 設計 → 實作 → 串接 → 測試 → 修正 → 上線 → 客戶驗收 → 維護
```

---

## 通用結構化提示設計法

將模糊需求轉換成高品質 Prompt，核心概念大致如下：

| 階段           | 說明   | 目的            |
| ------------ | ---- | ------------- |
| **Define**   | 定義任務 | 明確目標與需求       |
| **Describe** | 描述背景 | 提供上下文資訊       |
| **Direct**   | 指示行為 | 規範 AI 如何思考與輸出 |
| **Deliver**  | 定義產出 | 指定最終格式與品質要求   |

---

# 1. Define（定義任務）

先明確告訴 AI：

* 要做什麼
* 達成什麼目標
* 成功標準是什麼

### 不佳

> 幫我分析這篇論文

### 較佳

> 請分析此論文的研究問題、方法、實驗設計與主要貢獻，並評估其創新性與限制。

---

# 2. Describe（描述背景）

提供 AI 必要脈絡：

* 使用者身分
* 使用場景
* 領域知識
* 限制條件

### 範例

> 我是資訊工程研究生，正在閱讀 RAG 相關論文，需要快速掌握研究重點，並整理成文獻回顧筆記。

此時 AI 會調整解釋深度。

---

# 3. Direct（指示行為）

告訴 AI：

* 採用什麼角色
* 如何思考
* 評估標準
* 注意事項

### 範例

> 請以資深研究員角度分析。
>
> 分析時：
>
> 1. 先說明研究動機
> 2. 再拆解方法架構
> 3. 最後評估優缺點
>
> 不要產生未出現在論文中的內容。

---

# 4. Deliver（定義產出）

指定輸出格式。

### 範例

```markdown
# 論文摘要

## 研究問題

...

## 方法

...

## 優點

...

## 限制

...
```

---

# 完整範例

假設你常做論文整理：

```text
【Define】
分析論文核心貢獻與技術創新。

【Describe】
我是資訊工程研究生，正在撰寫文獻回顧，希望快速掌握研究重點。

【Direct】
請以資深 AI 研究員角度分析。

分析內容包含：
1. 研究問題
2. 方法架構
3. 創新點
4. 實驗結果
5. 研究限制

不得推測論文未提及內容。

【Deliver】

輸出格式：

# 論文名稱

## 一句話總結

...

## 研究問題

...

## 方法

...

## 創新點

...

## 研究限制

...
```
